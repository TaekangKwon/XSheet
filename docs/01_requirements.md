## TL;DR
- 目的：.xlsx を「Excel で開いたときと同じ見た目」で、ブラウザに速く安全に表示する部品を、どのアプリにも組み込めるようにする。
- やらない：書き込み・.xls・数式の計算・編集。必要なら SheetJS などと併用する。
- 守ること：外部通信をしない・壊れたファイルや巨大なファイルで固まらない（上限で止める）・核は DOM に依存しない。

---

## 1. 背景

- 設計書・仕様書として Excel を使う現場では、表の体裁（罫線・塗り・列幅・結合）と、貼られた画面写しや構成図（画像・図形・矢印）に情報がある。
- 既存のライブラリの状況：
  - SheetJS（npm の `xlsx` 0.18.5）は npm 版に既知の脆弱性（CVE-2023-30533・CVE-2024-22363）の修正が無い。
  - CDN 版も大きいシートで全シートを展開して固まる（6 秒以上）。
  - 書式・図の表示は有償版の範囲。
- InterHub と xrag-Viewer は、それぞれ自前のリーダーと表示を作った。同じものを 2 か所で直し続けないために、1 つのライブラリにまとめる。

## 2. 利用者と使い方

| 利用者 | 使い方 |
| --- | --- |
| ローカルの文書ビューア（InterHub・xrag-Viewer） | ファイルの `ArrayBuffer` を渡し、指定の要素の中にシートを表示する。タブ・枠・文言は自前 |
| Web アプリの開発者 | 添付の .xlsx のプレビュー。`renderWorkbook` でタブ付きの表示を丸ごと使う |
| 変換・検査のツール（Node・Worker） | 核だけを使い、セルの表示文字列・書式・罫線・図の一覧を取り出す |

## 3. 範囲

### やる（v1.0 まで）

| 区分 | 内容 | 元の Issue |
| --- | --- | --- |
| 読み取り | シートの一覧（非表示を含む）・セルの表示文字列（数値の表示形式を ssf で適用）・結合・1904 年基準 | 82 |
| 寸法 | 列幅・行高・既定値・非表示の行と列・既定フォントによる最大桁幅（MDW） | 83・84 |
| セル書式 | 塗り（模様・グラデーションは代表 1 色）・文字の色・太字・斜体・下線・取り消し線・文字サイズ・行と列の書式 | 99・100 |
| 罫線 | 13 線種・斜線・辺の優先・結合の外周 | 97・98 |
| 色 | テーマの 12 色・色の変換（lum・tint・shade・alpha など）・インデックス色 | 94・95 |
| 画像 | png・jpeg・gif・bmp・webp をセルの位置に重ねる | 85・86 |
| 図形 | 図形の文字・線と矢印・グループ・preset の形 176 種・自由図形・塗りと枠線の色 | 87〜93・96 |
| 表示 | 行と列の仮想化・ダーク表示・数値の右揃えと `###`・はみ出し文字 | 84・100 |

### やらない（範囲外）

| 項目 | 理由・代わり |
| --- | --- |
| 書き込み・編集 | 表示の部品に絞る。必要なら別のライブラリ |
| `.xls`（BIFF）・`.ods`・`.csv` | 形式ごとに別の解析器が要る。`.xls` は使う側で SheetJS へ振り分ける（InterHub の方式） |
| 数式の計算 | ファイルに保存された計算結果を表示する |
| グラフの描画 | 種類名入りの破線枠で位置だけ示す（将来の候補） |
| 条件付き書式・テーブルのスタイル・揃えと折り返し・フォント名・リッチテキストの部分書式 | 将来の候補（[04_roadmap.md](04_roadmap.md) M7） |

## 4. SheetJS との違い

| 観点 | SheetJS（Community） | XSheet |
| --- | --- | --- |
| 目的 | 多形式の読み書き・変換 | .xlsx を Excel どおりに表示 |
| 形式 | xlsx・xls・ods・csv ほか多数 | xlsx だけ |
| 書き込み | ○ | ✕ |
| 書式・罫線・図の表示 | ✕（Pro の範囲） | ○ |
| 大きいシート | 全体を展開する | 見えている行だけを展開（100 万セルで 0.5〜0.7 秒） |
| 表示部品 | 無し（HTML への書き出しのみ） | 仮想化した表示部品・ダーク表示 |
| 依存 | なし（自前の zip） | jszip・ssf |
| 生の値の取り出し（`sheet_to_json`） | ○ | M7 の候補（今は表示文字列と種類だけ） |

## 5. 非機能要件

| # | 要件 | 基準 |
| --- | --- | --- |
| N1 安全 | 外部通信をしない。`eval`・`new Function` を使わない | 静的検査とテストで確認 |
| N2 安全 | zip の展開量・部品の大きさ・件数に上限を設け、超えたら `XlsxError('too-large')` で止める | 上限は 25 項目（[02_architecture.md](02_architecture.md) §5）。使う側が変えられる |
| N3 安全 | 例外のメッセージにセル値・シート名を含めない | テスト |
| N4 性能 | 100 万セルのシートを 1 秒以内に開く。スクロールで 200ms を超えるフレームを出さない | 図形 1,000 個・全罫線 10,000 セルで確認済み（InterHub の実測） |
| N5 性能 | 解析は線形時間（悪意のある入力で二乗にならない） | `linear-time` のテスト（perf の project） |
| N6 容量 | 核・描画・形の表を別のチャンクにし、形の表（171 KB・gzip 約 28 KB）は図形を描くときだけ読む。各チャンクの上限は M4 で実測して決める（M4-2 で決めた。[02](02_architecture.md) §8「大きさ」・`npm run size`） | ビルドで計測（参考：xrag の初版は読み取り＋表示で 40,760 B、jszip 96,716 B。InterHub は図形の対応で dist が +177,565 B） |
| N7 CSP | `script-src 'self'` で動く。書式の `<style>` 要素に `style-src 'unsafe-inline'` か nonce が要る。画像に `img-src blob:` が要る | [02](02_architecture.md) §3「CSP」に明記。`nonce` を渡せる。`tests/render/csp.test.ts` と examples（nonce だけの `style-src`）で確認（M3-3） |
| N8 移植性 | 核は DOM・Node 固有の API を使わない | DOM は型の設定（`lib` に DOM を入れない）、Node は ESLint（ADR-0001）で確認 |
| N9 後始末 | `destroy()` で blob URL・リスナ・ブックを全部放す | 漏れ 0 のテスト |
| N10 互換 | Excel 16 の表示と、寸法・図の位置は 1px 以内 | 照合の手順（[05_quality.md](05_quality.md)） |
