# 0009. リッチテキストの部分の書式

> 版: 1.0 ・ 更新日: 2026-11-17 ・ 担当: kwon
> 関連文書: [0008](0008-align-wrap-spill.md)（配置・はみ出し） / [0007](0007-moobius-viewer-api.md)（§2 ハイライト・§3 移動） / [0003](0003-universal-distribution.md)（§4-1 写しの規約） / [01_requirements](../01_requirements.md)（M7 の候補「リッチテキストの部分書式」）

## TL;DR
- 文字列のセルの `<r>`（1 つのセルの中で書式の違う区切り）を読み、`CellView` に `runs`（区切りの文字と書式）を足す（公開の型が増える）。
- 描くときは区切りごとに span を作り、色・太字・斜体・下線・取り消し線・文字の大きさを当てる。検索の一致の片（`.xs-hit`）は区切りをまたいでも 1 つの片のまま、その中を区切りで分ける。
- 移動の横の位置・判定・はみ出しの幅の見積もりも、区切りの書式で測る。
- 版は 0.6.0 に入れる（ADR-0008 と同じ版。公開の型が増えるため）。

## コンテキスト

- 今は `shared-strings.ts`・`sheet.ts` が `<r>` の `<t>` を連結して平文にし、区切りの書式（`<rPr>`）を捨てる（README の「まだ描かないもの」）。
- 写しの規約（ADR-0003 §4-1）：`shared-strings.ts`・`sheet.ts`・`cell-format.ts`・`types.ts`・`grid-table.ts` は InterHub の写し。処理は新しいファイル（`src/core/rich-text.ts`・`src/render/rich-text.ts`）に置き、写したファイルには `// XSheet:` の印の付いた口だけを足す。

## 決定

### 1. 読み取り（core）

```ts
/** 区切りの書式。区切りに `<rPr>` があれば、セルの書式の代わりにこれで描く（持たない項目は既定＝太字なし・自動の色・既定の大きさ） */
export type RunFont = Pick<CellFormat, 'color' | 'bold' | 'italic' | 'strike' | 'underline' | 'sizeRatio'>;

export interface TextRun {
  /** 区切りの文字（`runs` の `text` を連結すると `CellView.text`） */
  text: string;
  /** `<rPr>` のある区切りの書式。無ければセルの書式のまま */
  font?: RunFont;
}

export interface CellView {
  // …今の項目…
  /** リッチテキストの区切り。`<rPr>` のある区切りが 1 つも無い文字列は持たない */
  runs?: readonly TextRun[];
}
```

- 対象は共有文字列（`t="s"`）と inlineStr の `<r>`。数式の結果（`t="str"`）は平文しか無いので持たない。
- `<rPr>` の子は `<font>` と同じ読み方（`cell-format.ts` の `readFont`：太字・斜体・取り消し線・下線・色・大きさの比。色はテーマで解く。不透明な黒は自動に寄せる）。基準の大きさは先頭の `<font>` の `sz`。フォント名（`rFont`）・上付き・下付き（`vertAlign`）は読まない。
- `<rPr>` のある区切りは、セルの書式を継がずに区切りの書式だけで描く（Excel は区切りの `<rPr>` をその区切りのフォントとして使う）。`<rPr>` の無い区切りはセルの書式のまま。
- 区切りの文字を連結したものが平文（ふりがなを除いた `<t>` の連結）と違うとき（`<si>` の直下の `<t>` と `<r>` が混ざるなど）は `runs` を持たない（平文で描く）。空の区切りは捨てる。文字を `MAX_CELL_TEXT` で切ったときは区切りも同じ位置で切る。
- styles.xml が無い・壊れている（書式の表が空）ブックでは区切りの書式を読まない（色を解く表が無いため）。

### 2. 描き方（render）

- 入れ物（`.xs-cell`）・はみ出しの span（`.xs-text`）の文字を、区切りごとの子に置き換える。`font` の無い区切りはテキストノード、ある区切りは span に CSSOM（`style.setProperty`）で書式を当てる（値は整数・真偽から組み、ファイルの文字列を入れない）。
  - 色：`font.color` があればその色。無く、セルの書式に色があれば自動の色（塗りの上は黒、ほかは `--xs-fg`）。どちらも無ければ当てない（セルの自動の色を継ぐ。`inkSpill` の塗り分けもそのまま効く）。
  - 太字・斜体：有無を明示（`700`/`400`・`italic`/`normal`）。
  - 下線・取り消し線：区切りにあれば当てる。セルの書式の線は子で消せない（CSS の `text-decoration` は子へ伝わる）。まれなので制約にする。
  - 大きさ：`区切りの比 ÷ セルの比` を em で当てる。
- 検索の一致（`decorateCell`）：一致の片の外と中の文字を、どちらも区切りで分けて入れる。片は今のとおり一致ごとに 1 つ（番号・今のヒットの印は変わらない）。
- 収まらない数値（`###`）は文字列ではないので関係しない。折り返し・配置（ADR-0008）はそのまま効く。

### 3. 測り方（render）

- 移動の横の位置（`matchRange`）とはみ出しの判定（`reaches`）は、測る span に区切りの子を入れて測る（太字・大きさの違う区切りでも一致の位置がずれない）。
- 最終列からのはみ出しの見積もり（`estimateCellTextWidth`）は、区切りごとに大きさの比と太字・斜体を当てて足す。

## 却下した案

| 案 | 却下した理由 |
| --- | --- |
| 区切りの書式を `CellFormat` の番号（書式の表）で持つ | 書式の表はセルの xf の位置から引く表で、区切りは xf を持たない。表の数え方（`maxCellFormats`）も変わる |
| 区切りの書式をセルの書式に重ねる（持たない項目はセルから継ぐ） | Excel の見え方と違う（`<rPr>` のある区切りはその書式だけで描かれる） |
| 一致の片を区切りごとに分ける | 1 つの一致が複数の片になり、`highlightAt`・今のヒットの印が片の数だけ増える |

## 結果

- 良い点：Excel の部分の色・太字などが見える。検索・移動・判定は区切りをまたいでも今のとおり。
- 注意：`CellView` に項目が増える（0.6.0）。区切りのあるセルは DOM の要素が増える。
- 注意：セルの書式の下線・取り消し線は、区切りの書式で消せない。フォント名・上付き・下付きは描かない。
