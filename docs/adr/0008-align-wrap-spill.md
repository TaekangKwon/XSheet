# 0008. セルの配置・折り返しと、最終列からのはみ出し（Moobius の依頼 R8・R9）

> 版: 1.0 ・ 更新日: 2026-11-16 ・ 担当: kwon
> 関連文書: [0007](0007-moobius-viewer-api.md)（§3・§4・§8 の続き） / [0003](0003-universal-distribution.md)（§4-1 写しの規約） / [01_requirements](../01_requirements.md)（M7 の候補「揃えと折り返し」）

## TL;DR
- R8：表の右端を、最後の列からはみ出す文字の右端まで広げる。はみ出しの幅は**文字数からの多めの見積もり**で決め、描いた行と移動先の行から**必要になった時点で広げる**（シートを開くときに全行を読まない）。
- R9：`<xf>` の `<alignment>` の horizontal・vertical・wrapText を読み、`CellFormat` に `hAlign`・`vAlign`・`wrap` を足す（公開の型が増える）。描くときは入れ物のクラスで配置を当て、右寄せは左へ、中央は両側へはみ出させる。折り返したセルははみ出さない。
- 移動（`focusHighlight`）の横の位置は、配置ごとに文字の左端を出し直す。折り返したセルはセルの範囲へ移動する。
- 版は 0.6.0（公開の型が増えるため）。

## ステータス

accepted（2026-11-16）。ユーザーが「自分だけでできる作業を先に進め、ユーザーの確認は後にまとめる」と指示したため、推奨のまま決めて実装した。確かめるのは §6。

## コンテキスト

- 依頼（2026-11-16・R8・R9）。v0.5.0 で依頼の自己テストが R8 3 件・R9 10 件 NG。完了の条件は両方の NG が 0、R1〜R7 が OK のまま。
- R8 の原因：表の列数は `gridExtent`（`grid.ts`）が「データの列数・図の右端・枠を埋める列数」の最大で決める。データが表示枠より右へ続くシート（06_検索 は BH 列まで）は、表が最後のデータ列で終わる。はみ出しの列数を数える `spillColumns` も表の列数で止まるため、最後の列の文字が切れ、そこにある一致へは移動も判定もできない。
- R9 の原因：`styles.ts`・`cell-format.ts` が `<alignment>` を読まない。配置はセルの型だけで決まり（`cellAlignClass`）、表は `white-space: nowrap` で 1 行に描く（ADR-0007 §8 で受け入れから外した項目）。
- 写しの規約（ADR-0003 §4-1）：`cell-format.ts`・`grid.ts`・`grid-table.ts`・`sheet-view.ts`・`style.css`・`make-xlsx.ts` は InterHub の写し。処理は新しいファイル（`src/core/cell-align.ts`・`src/render/cell-align.ts`）に置き、写したファイルには `// XSheet:` の印の付いた呼び出しの口だけを足す。

## 決定

### 1. 配置の読み取り（R9・core）

```ts
export interface CellFormat {
  // …今の項目…
  /** 横の配置（XSheet: ADR-0008）。標準（general）は持たない＝型で決める（数値・日付は右、真偽・エラーは中央、文字列は左） */
  hAlign?: 'left' | 'center' | 'right';
  /** 縦の配置（XSheet: ADR-0008）。下（bottom・既定）は持たない */
  vAlign?: 'top' | 'center';
  /** 折り返して全体を表示する（XSheet: ADR-0008） */
  wrap?: true;
}
```

- `<xf>` の子の `<alignment>` を読む。`applyAlignment` は見ない（塗り・文字の装飾と同じ。F5）。cellStyleXfs は読まない。
- horizontal の対応：`left`・`center`・`right` はそのまま。`distributed`・`fill`・`justify` は `left`（依頼のとおり）。`centerContinuous` は `center`。`general`・不明・無しは持たない。
- vertical の対応：`top`・`center` はそのまま。`justify`・`distributed` は `top`（Excel は上から詰める）。`bottom`・不明・無しは持たない。
- wrapText：`1`・`true` のときだけ `wrap: true`。
- 配置だけの xf も「見える書式」になり、同じ見た目の書式をまとめるキーに配置を足す（`maxCellFormats` の数え方は今と同じ）。
- 走査は線形（`<xf>`・`</xf>`・`<alignment>` の開きタグを 1 本の正規表現で順に拾う）。閉じの無い xf があっても先へ読み進めない。

### 2. 配置の描き方（R9・render）

- 入れ物（`div.xs-cell`）にクラスを足す。書式ごとの CSS の規則（`format-css.ts`）には足さない（はみ出しの計算が配置を知る必要があり、DOM の組み立てで一緒に決めるため）。

| 指定 | クラス | CSS |
| --- | --- | --- |
| 横 左（文字列以外にも効く） | （なし） | 左から |
| 横 中央・右（数値・日付・真偽・エラー） | 今の `is-center`・`is-right` | `safe`（収まらない `###` は左から） |
| 横 中央・右（文字列） | `is-h-center`・`is-h-right` | `safe` を付けない（文字の中央・右端をセルに合わせ、はみ出さない側を切る） |
| 縦 上・中央 | `is-v-top`・`is-v-center` | `align-items` |
| 折り返し | `is-wrap` | `white-space: pre-wrap`・`overflow-wrap: anywhere`・`text-align` |

- 結合セルは今も入れ物が結合の範囲いっぱい（幅は `colSpan`・高さは `spanHeight`）なので、配置は結合の範囲全体に当たる。
- 折り返しは入れ物の幅（列幅・結合なら結合の幅）で行い、文字の中の改行を残す。行の高さは変えず、収まらない分は切る（縦の配置の向きに切れる）。折り返しの無いセルの改行は今のとおり空白に見える（Excel と同じ）。

### 3. はみ出しの向き（R9・render）

- はみ出すのは今と同じく、型が文字列で値のある、結合の無いセルだけ。折り返すセルははみ出さない。
- 右へ数える列は今の `spillColumns`。左へも同じ条件で空のセルを数える（描く列の範囲の左端・値のあるセル・結合で止める）。
  - 左寄せ・標準・`distributed`・`fill`：右だけ（今と同じ）。
  - 右寄せ：左だけ。入れ物を `margin-left` で左へ広げ、文字の右端は元のセルの右端のまま。
  - 中央：両側。入れ物を両側へ広げ、左右の余白で文字の中心を元のセルの中心に合わせる（片側が値のあるセルで止まっても中心は動かさず、その側を切る）。
- 塗りが絡むときの `is-over-fill` は、広げた全部の列で判定する。列ごとの自動の文字色の塗り分け（`inkSpill`）は右へのはみ出しだけに残す（左・両側では単色。まれなので制約にする）。
- 位置の判定（`cellAt`）は、左右の値のあるセルを辿り、そこから届くはみ出しの元を返す（左寄せは左から、右寄せは右から、中央は両側から）。

### 4. 最終列からのはみ出し（R8・render）

- 表の列数の最小に「はみ出しが届く列」を足す（`gridExtent` の `minCols` へ、図の右端と大きい方を渡す）。
- 届く列は、行ごとに「値のある最後のセル」が文字列ではみ出せるときだけ、`列の左端 + 文字の幅の見積もり`（中央は半分）を含む列とする。見積もりは文字数から多めに出す（全角 1em・ほかは 0.7em、文字の大きさは表の 13px × `sizeRatio`、左右の余白を足す）。多めに出た分は空の列が増えるだけで、文字は切れない（依頼は「空の列を描いてよい」）。DOM で測らない。
- 調べるのは、描いた行（描くたび。読んだ行をそのまま使う）と、移動先の行（`focusHighlight`・`scrollToCell` の前）。シートを開くときに全行は読まない（大きなシートで開くのを遅くしない）。広がった列数はシートを替えるまで保つ（狭めない）。
  - 結果：表の幅は、はみ出す行を描いたとき・そこへ移動したときに広がる。横のスクロールの幅が縦のスクロールの途中で一度だけ伸びることがある。
- 幅に合わせる倍率（fit）の計算には含めない（依頼で任意。中身の幅が描く位置で変わると倍率が揺れるため）。

### 5. 移動の横の位置（R3 の続き）

- 文字列の一致の横の範囲（`matchRange`）を配置ごとに出す。文字全体の幅 `W` と一致の前・後までの幅を測り、文字の左端を左寄せ＝セルの左端＋3px、右寄せ＝セルの右端−3px−`W`、中央＝セルの中心−`W`/2 とする。
- 折り返すセルは、一致の範囲を測らずセルの範囲へ移動する（文字はセルの中にあるため）。

### 6. 確かめ方

- 単体テスト：配置の読み取り（`cell-format`）・はみ出しの左右の列数・入れ物のクラスと幅・判定・移動の横の位置・表の列数の広がり。テストのファイルは `make-xlsx.ts` で作る（依頼のサンプルはリポジトリに入れない）。
- 実機：依頼のサンプル `compare_features.xlsx`（リポジトリの外）を開発サーバーで開き、依頼の表のセル（01_書式 C22〜C31・04_結合 B5:D7・B9:E9・06_検索 BH3・BH1500）を目視と `cellAt`・`highlightAt` で確かめる。依頼の自己テストは手元に無いので、ユーザーに依頼の側で回してもらう。

## 却下した案

| 案 | 却下した理由 |
| --- | --- |
| 表を常に一定の列数（例：データ＋1 画面）だけ右へ足す | 足した幅より長い文字は切れる。短い文字しかないシートでも右に空の画面が増える |
| シートを開くときに全行を読んで、はみ出しの右端を決める | 大きなシートで開くのが遅くなる（`getRows` が行を作り直す）。必要な行だけで足りる |
| はみ出しの幅を DOM で測る | 描く前（移動先の計算）に測れない行がある。測ると描くたびにレイアウトが走る |
| 配置を書式の CSS の規則（`xs-xf-<番号>` の td）に入れる | はみ出しの向きと幅は配置で変わり、DOM を組むときに配置を知る必要がある。規則と組み立ての 2 か所に分かれる |
| インデント・回転・縮小して全体を表示 | 依頼で不要 |

## 結果

- 良い点：Excel の配置・折り返しで描ける。最後の列の文字が切れない。公開の API の形（関数）は変わらない。
- 注意：`CellFormat` に項目が増える（0.6.0）。配置だけの xf も書式の番号を持つので、書式の表が少し増える。
- 注意：表の幅が描いた行で後から広がる。左・両側へのはみ出しで、塗りをまたぐ自動の文字色は塗り分けない。
- 注意：`make-xlsx.ts` の xf に入っていた `<alignment vertical="top"/>` を既定で外した（入れたままだと合成したテストのセルがすべて上寄せになる）。配置は `xfAlignments` で指定する。
